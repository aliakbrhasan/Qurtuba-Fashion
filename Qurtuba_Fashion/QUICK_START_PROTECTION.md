# دليل سريع لحماية الكود المصدر

## 🚀 خطوات سريعة

### 1. تثبيت المكتبات المطلوبة
```bash
npm install
```

### 2. بناء التطبيق مع الحماية
```bash
npm run build:secure
```

أو للبناء الكامل مع Electron:
```bash
npm run electron:build:secure
```

---

## 📋 ما الذي تم إضافته؟

### ✅ تقنيات الحماية المطبقة:

1. **التعتيم (Obfuscation)**
   - تعقيد الكود بشكل كبير
   - ترميز النصوص والمتغيرات
   - إخفاء بنية الكود

2. **Minification متقدم**
   - ضغط الكود
   - إزالة التعليقات
   - تحسين الأداء

3. **إزالة Source Maps**
   - لا توجد ملفات source maps في النسخة المحمية
   - صعوبة ربط الكود المعتم بالكود الأصلي

4. **ASAR Packaging** (مفعّل مسبقاً)
   - حزم الملفات في أرشيف ASAR
   - حماية إضافية في Electron

---

## 📁 الملفات المهمة

- `CODE_PROTECTION_GUIDE_AR.md` - دليل شامل للحماية
- `NDA_TEMPLATE_AR.md` - قالب اتفاقية عدم الإفصاح
- `scripts/obfuscate-build.js` - سكربت التعتيم

---

## ⚠️ تحذيرات

1. **الكود المعتم أبطأ قليلاً** (5-10%)
2. **صعوبة Debugging** - لا يمكن التصحيح في الكود المعتم
3. **الحماية التقنية وحدها لا تكفي** - يجب إضافة NDA

---

## 🔐 التوصيات

### قبل التسليم:

1. ✅ استخدام `npm run build:secure`
2. ✅ طلب توقيع NDA من العميل
3. ✅ إزالة ملفات `.ts` الأصلية من النسخة المسلمة
4. ✅ التأكد من عدم وجود Source Maps

### ما يجب تسليمه:

- ✅ ملفات `build/` فقط (الكود المعتم)
- ✅ ملفات `dist-electron/` (الكود المترجم)
- ✅ ملف `package.json` (دون معلومات حساسة)
- ❌ **لا** تسلم ملفات `src/`
- ❌ **لا** تسلم ملفات `electron/` الأصلية

---

## 🧪 اختبار الحماية

بعد البناء، افتح ملف في `build/assets/*.js` وتحقق من:
- الكود غير قابل للقراءة
- أسماء المتغيرات مبدلة (مثل `_0x1a2b3c`)
- النصوص مشفرة (base64)
