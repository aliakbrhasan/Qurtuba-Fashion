# دليل حماية الكود المصدر - أزياء قرطبة

## نظرة عامة

هذا الدليل يشرح الطرق المتاحة لحماية الكود المصدر عند مشاركته مع العملاء للاختبار.

## ⚠️ ملاحظة مهمة

**لا يوجد حماية 100% للكود المصدر في JavaScript/TypeScript**. أي كود يعمل في المتصفح يمكن فك تشفيره بجهد كافٍ. لكن يمكننا جعل العملية صعبة جداً وتستغرق وقتاً طويلاً.

---

## 🔒 خيارات الحماية المتاحة

### 1. الحماية التقنية (Technical Protection)

#### ✅ أ) التعتيم (Obfuscation)
- **ما هو**: تحويل الكود إلى شكل صعب القراءة ولكن يعمل بنفس الطريقة
- **المميزات**: صعب جداً القراءة، يحمي أسماء المتغيرات والوظائف
- **العيوب**: يمكن فكه بجهد كبير
- **الحل المطبق**: تم إضافة `javascript-obfuscator` في المشروع

#### ✅ ب) Minification
- **ما هو**: ضغط الكود وإزالة المسافات والتعليقات
- **الحالة**: مفعّل تلقائياً في Vite
- **المستوى**: حماية أساسية فقط

#### ✅ ج) ASAR Packaging
- **ما هو**: حزمة Electron التي تحزم الملفات في أرشيف ASAR
- **الحالة**: مفعّل في `electron-builder.json`
- **المستوى**: حماية متوسطة (يمكن استخراج ASAR بسهولة)

#### ✅ د) إزالة Source Maps
- **ما هو**: عدم إنشاء ملفات Source Maps التي تربط الكود المضغوط بالكود الأصلي
- **الحالة**: تم تفعيله في الإعدادات

---

### 2. الحماية القانونية (Legal Protection)

#### ⚖️ أ) اتفاقية عدم الإفصاح (NDA)
**الأهمية**: هذا أهم من الحماية التقنية!

**يجب أن يتضمن:**
- منع النسخ والتوزيع
- منع الإصلاح والبيع
- منع مشاركة الكود مع أطراف ثالثة
- تحديد فترة الحماية
- العقوبات المالية للمخالفة

**ملف قالب**: يمكن إنشاء ملف `NDA_TEMPLATE.md` كمثال

#### 📝 ب) رخصة الاستخدام (License Agreement)
- إضافة رخصة في ملف `LICENSE` في المشروع
- تحديد شروط الاستخدام المقصودة فقط

#### 📧 ج) وثائق محددة
- تسليم الكود عبر قناة آمنة
- توثيق كل شيء يتم تسليمه

---

### 3. الحماية الإدارية (Administrative Protection)

#### 🔐 أ) الوصول المحدود
- تسليم نسخة للاختبار فقط (ليس للتصحيح)
- تحديد فترة الاختبار
- طلب إرجاع أو حذف الكود بعد الاختبار

#### 👥 ب) تحديد الأشخاص
- تحديد الأشخاص المصرح لهم فقط بالوصول
- طلب توقيعات على NDA من كل شخص

---

## 🚀 التنفيذ المطبق في المشروع

### تم إضافة:

1. **JavaScript Obfuscator Plugin**
   - حزمة: `rollup-plugin-obfuscator`
   - مستوى تعتيم عالي
   - يحمي أسماء المتغيرات والوظائف

2. **إعدادات Build محسّنة**
   - إزالة Source Maps في الإنتاج
   - Minification قوي
   - ضغط الكود

3. **سكربتات Build خاصة**
   - `npm run build:secure` - بناء مع حماية كاملة
   - `npm run build:client` - بناء للعميل مع التعتيم

## 📋 خطوات الاستخدام

### للبناء مع الحماية الكاملة:

```bash
# بناء التطبيق مع التعتيم الكامل
npm run build:secure

# بناء للتوزيع على العميل
npm run build:client
```

### ملفات الإخراج:

- `build/` - ملفات React المضغوطة والمعتمة
- `dist/` - ملفات Electron النهائية

## ⚙️ الإعدادات الحالية

### مستوى التعتيم (في `vite.config.ts`):

```javascript
compact: true,           // ضغط الكود
controlFlowFlattening: true,  // تعقيد تدفق الكود
deadCodeInjection: true,      // إضافة كود ميت
stringArray: true,            // تعتيم النصوص
stringArrayEncoding: ['base64'], // ترميز النصوص
```

## 🔍 كيفية الاختبار

### 1. اختبار أن التطبيق يعمل:
```bash
npm run build:secure
npm run electron:dev
```

### 2. فحص الملفات المعتمة:
افتح `build/assets/*.js` وتحقق من:
- الكود غير قابل للقراءة
- أسماء المتغيرات مبدلة
- النصوص مشفرة

## 📊 مستويات الحماية

| الحماية | المستوى | الصعوبة في الفك |
|---------|---------|-----------------|
| Minification فقط | ⭐ | سهل |
| Obfuscation أساسي | ⭐⭐ | متوسط |
| Obfuscation قوي (الحالي) | ⭐⭐⭐ | صعب جداً |
| Obfuscation + NDA | ⭐⭐⭐⭐ | صعب جداً + قانوني |

---

## ⚠️ تحذيرات مهمة

1. **الكود المعتم قد يكون أبطأ قليلاً** (حوالي 5-10%)
2. **الحجم قد يزيد قليلاً** (حوالي 10-20%)
3. **صعوبة Debugging** - لا يمكن التصحيح في الكود المعتم
4. **الحماية التقنية وحدها لا تكفي** - يجب إضافة NDA

---

## 📞 التوصيات النهائية

### ✅ يجب فعله:

1. ✅ استخدام `npm run build:secure` قبل التسليم
2. ✅ طلب توقيع NDA من العميل
3. ✅ توثيق ما تم تسليمه
4. ✅ تحديد فترة الاختبار
5. ✅ طلب إرجاع أو حذف الكود بعد الاختبار

### ❌ يجب تجنبه:

1. ❌ تسليم الكود الأصلي بدون NDA
2. ❌ تسليم Source Maps
3. ❌ تسليم ملفات `.ts` الأصلية
4. ❌ السماح بالوصول للكود بدون قيود
